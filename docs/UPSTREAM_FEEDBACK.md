# Upstream feedback review

Reviewed on 2026-10-11 for Earth Observer's compact public-hosting baseline. This is a product triage, not an assertion that upstream proposals or downstream pull requests have shipped.

## Evidence and coverage

The [upstream issue tracker](https://github.com/bilawalsidhu/gods-eye-view/issues) was read through the public GitHub API with pagination: 319 issues, including 85 open and 234 closed; pull requests were excluded. Open titles were inventoried, relevant issue bodies were read, and saved-place, keyboard-palette, evidence-handoff, and accessibility discussions were inspected. Counts are a dated snapshot.

A separate [official YouTube feedback review](YOUTUBE_FEEDBACK.md) retrieved and read 300 top-sorted, top-level public comments: 100 each from [the open-source launch](https://www.youtube.com/watch?v=GRJaKcXZS94), [the Iran/4D demonstration](https://www.youtube.com/watch?v=0p8o7AeHDzg), and [the original weekend build](https://www.youtube.com/watch?v=rXvU7bPJ8n4). The report links 26 selected comment IDs and explains the sorting/no-reply sample limits. Themes relevant here include simpler hosted access, fewer effects, source certainty, observation dates, coverage gaps, historical context, and reuse rights. This is a bounded sample, not a majority survey. An initial check of a different walkthrough page returned HTTP 429; that page-specific failure does not negate the successful sample. No private-account access or traffic bypass was used. The concrete favorites/palette proposals below come from GitHub; YouTube feedback independently supports the simpler interface and honest source context.

## Performance follow-up

[#962](https://github.com/bilawalsidhu/gods-eye-view/issues/962) proposes pausing optional imagery refinement during camera motion, keeping the last committed visual, and rejecting obsolete completion callbacks. This fits the earlier smoothness request, but it should remain a measured rendering task rather than a new refresh owner. Provider freshness intervals must remain unchanged. Tests should show zero optional requests during motion, one coalesced pass after settling, no obsolete render wakeup, and deterministic teardown. Do not copy a downstream branch wholesale or claim a speed improvement before the A/B measurement exists.

## Deferred scope

- [#890: KML/GPX import](https://github.com/bilawalsidhu/gods-eye-view/issues/890) is a plausible later personal-data feature, but file limits, XML parsing, network-link handling, validation, and export deserve a separate change.
- [#48: deployment convenience](https://github.com/bilawalsidhu/gods-eye-view/issues/48) belongs to the hosting pass. Live feed proxies require a server deployment; a static-only upload does not replace that server.
- [#963: disaster route access](https://github.com/bilawalsidhu/gods-eye-view/issues/963), [#989: cockpit/bridge views](https://github.com/bilawalsidhu/gods-eye-view/issues/989), and voice/agent automation do not justify reintroducing simulation, inference-driven safety labels, or the removed cockpit dependencies.
- Additional camera packs, network-device maps, private TAK feeds, commercial aircraft feeds, 3D map services, and forest-monitoring datasets need their own documented access, capacity, redistribution, and attribution review. Public visibility or a free account does not establish hosting rights.
- The implemented public community queue needs host identity/storage/moderation configuration before accepting submissions. Public browsing exposes approved material only. Local notebook notes remain private and are never uploaded automatically.

Only evidence-linked, bounded features should be adapted. Upstream issue text is a request, not proof that its proposed provider terms or implementation are suitable for this hosted fork.
