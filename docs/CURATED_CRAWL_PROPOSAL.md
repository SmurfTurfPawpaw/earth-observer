# Curated metadata ingestion proposal

Research date: 2026-10-11. NASA EONET's bounded acquisition, reader and discovery
integration are implemented and under release validation; publication and job
activation are recorded separately in [the evidence audit](GOAL_AUDIT.md).
ReliefWeb remains a proposal. This reviews these two curated APIs, not every
publisher linked by either service.

Implement **NASA EONET v3 first**, as a small addition to disaster discovery.
Keep **ReliefWeb as a gated follow-up** for humanitarian reporting. Both are
curated API sources; neither proposal follows links to crawl publisher pages.
EONET does not supply general geopolitical or economic news.

## NASA EONET: viable without registration

NASA describes EONET as continuously updated natural-event metadata intended
for application display. Its documented v3 requests and client examples do not
require an API key. [EONET overview](https://eonet.gsfc.nasa.gov/),
[official client guide](https://eonet.gsfc.nasa.gov/how-to-guide).

The disclaimer limits its use to visualization and general information:
locations and temporal extents can be approximate, and are not authoritative
incident boundaries. Preserve that qualification on every source card.
[EONET disclaimer](https://eonet.gsfc.nasa.gov/what-is-eonet).

The [NASA data-license guidance](https://science.data.nasa.gov/about/license)
distinguishes mission data from other data whose original rights must be
checked. Do not label the entire EONET feed or its linked publishers CC0. The
documented metadata-display purpose supports a factual discovery index; it
does not license article bodies, photos, imagery or attachments. Use plain-text
credit `NASA EONET · referenced sources: <source IDs>` with links to EONET and
each retained source URL. This attribution is our conservative display policy,
not a claim that EONET prescribes this exact wording.

Direct read-only checks found:

- [EONET robots.txt](https://eonet.gsfc.nasa.gov/robots.txt): HTTP 200 with
  `User-agent: *` and an empty `Disallow` directive.
- [One-event request](https://eonet.gsfc.nasa.gov/api/v3/events?status=all&days=7&limit=1):
  HTTP 200 without credentials, 12,716 bytes, under a 64 KiB research cap.
  It returned event `EONET_5359`, with NATICE source attribution and geometry
  dates from 2021 through 2026-10-09. Thus `days=7` must not be treated as a bound
  on the geometry history returned for a matching event.
- The response had `Cache-Control: no-cache, private` and no ETag or
  Last-Modified. Do not put the raw upstream response in a shared HTTP cache.
  The proposed published artifact is a normalized metadata index, with its own
  retrieval provenance, not a transparent cached API response.

No numeric request quota, required retention period or precise refresh SLA was
found in the reviewed EONET documentation. The limits below are application
choices. Curation is selective; feeds can share an underlying source such as
GDACS and cannot be counted as independent confirmation.
[Official curation criteria](https://eonet.gsfc.nasa.gov/event-curation).

### Fixed acquisition and record contract

Use only this fixed HTTPS request, generated by code:

```text
https://eonet.gsfc.nasa.gov/api/v3/events?category=wildfires,severeStorms,volcanoes&status=all&days=7&limit=60
```

These category/status/day/limit parameters are documented in
[EONET v3](https://eonet.gsfc.nasa.gov/docs/v3). Do not accept visitor URLs,
source filters or free queries. Do not fetch source links or imagery layers.

Retain a strict factual field selection: event ID and compact event title;
category ID/title; source ID/HTTP(S) URL; `closed`; and the latest valid source
geometry date as `sourceGeometryAt`. Use the canonical event API link as the
record URL. Drop descriptions, magnitudes until units are separately reviewed,
coordinates, polygons and geometry history in the first version.

Use `sourceId: "eonet"`, `kind: "curated-event"`, `category: "disasters"`.
Keep `publishedAt`, `observedAt` and `publisherCountry` null: an EONET geometry
date is not an article publication time or a verified incident time. Display
`EONET geometry date`, `EONET closed date` and our `Retrieved` separately.
No country tag is supplied; country-filtered searches should mark this source
not applicable rather than infer a country from its title or coordinates.

## ReliefWeb: useful after its access gate

ReliefWeb provides curated humanitarian reports through its read-only v2 API.
Its terms permit API use, while original contributors may retain copyright.
The documented ceilings are 1,000 calls/day and 1,000 entries/call; the service
does not guarantee data accuracy. These facts do not establish a blanket
license for every report. [API terms and quotas](https://apidoc.reliefweb.int/).

A pre-approved `appname` has been mandatory since 2025-11-01. The
[official request process](https://apidoc.reliefweb.int/parameters#appname)
requires ReliefWeb review; no registration or approval was obtained here.

Direct checks of [site robots](https://reliefweb.int/robots.txt) found search,
paginated river and RSS restrictions. [API robots](https://api.reliefweb.int/robots.txt)
returned `Disallow: /`. Do not turn this proposal into a generic crawler.
Before enabling a job, obtain the approved API-client appname and resolve
permission for this public metadata-index use, including the robots policy.
The existence of API documentation is not asserted to override robots rules.

The candidate endpoint is fixed:

```text
https://api.reliefweb.int/v2/reports?appname=<approved-configured-value>
```

Use a read-only POST query with `profile: "minimal"`, explicit field includes,
`status: "published"`, and a frozen `date.changed` range. Do not use `preset:
"latest"` as the public-status gate: its documented report filter also includes
`to-review`. [Preset definitions](https://apidoc.reliefweb.int/presets),
[request parameters](https://apidoc.reliefweb.int/parameters).

Candidate factual fields are ID, canonical URL, original-source URL (`origin`),
source ID/name, country ISO3/name, primary-country designation, theme and format
IDs, disaster reference IDs, and original/created/changed dates. The latter
mean original publication, addition to ReliefWeb and modification on ReliefWeb
respectively. Country tags describe report coverage, not a precise incident
location or publisher domicile. [Official field definitions](https://apidoc.reliefweb.int/fields-tables).

Display original organizations plus `via ReliefWeb`, and preserve both links.
Do not apply a CC license to the record merely because ReliefWeb hosts it. Omit
third-party titles until their use is reviewed; initially generate a clearly
labeled compact report label from vetted taxonomy. Never collect body/HTML,
summaries, files, previews or images. No general cache-retention duration was
found in the reviewed current API terms. The API updates when content is added;
that describes ingestion freshness, not the date of an underlying incident.
[ReliefWeb freshness FAQ](https://apidoc.reliefweb.int/faq).

## Smallest implementation

1. **Acquire:** a single GitHub Actions job every 30 minutes performs one EONET
   request, with a 15-second timeout, 2 MiB decompressed response cap, at most 60
   events and no redirects. Bound strings, dates and source lists; reject
   malformed responses. This is at most 48 scheduled requests/day. Honor 429
   Retry-After and exponential backoff; failure does not overwrite last-good
   data. Record the fixed query, attempted/succeeded times, actual count,
   truncation and gaps. Refresh cadence is a policy, not an EONET guarantee.
2. **Index:** normalize to at most 100 KiB and publish one complete
   `eonet.snapshot.json` artifact under the existing owned `intelligence-data`
   release. Identity is source ID plus EONET event ID; a source-generation hash
   replaces that whole bounded sample. Store only this normalized last-good
   generation in R2. Keep the original source dates when re-serving. Propose
   30-minute reader freshness, explicit stale status up to 24 hours after the
   last successful retrieval, then unavailable; these are our expiry limits.
3. **Rank and serve:** extend the existing shared index with the explicit
   `curated-event` kind and date semantics, rather than its current fallback
   classification as a hazard report. Add a fourth source to the source
   iteration (currently limited to three). Sixty EONET rows raise the current
   440-row API ceiling to at most 500, within the reusable 600-record/2 MiB
   bounds. Preserve metadata match explanations; disable incident navigation
   and independent-confirmation grouping for these records. Browser search
   remains local; it never drives upstream acquisition.
4. **Later ReliefWeb:** after approval, use one bounded hourly delta query plus
   a daily authoritative rolling-window reconciliation. Freeze range endpoints
   across at most three pages of 100 records, overlap the watermark by an hour,
   deduplicate by report ID/changed date, and advance it only after a complete
   successful run. Treat page/size limits as incomplete coverage. Reconciliation
   must remove withdrawn/missing records rather than keep every prior report.
   Recheck provider headers, metadata rights and vocabulary with approved
   small samples before choosing public artifact retention.

For both sources, a policy record should distinguish API access, permitted
metadata use, linked-content rights, review date and approval reference. A
source URL is provenance and an outbound link, never permission to follow it.
Demand may adjust selection among already acquired, reviewed topics within
the same bounds; it must not supply arbitrary crawl URLs or raw private
queries. Synthetic agent journeys remain excluded from demand counts.

Implementation fixture tests cover malformed/oversized input,
future and missing dates, closed status, years of geometry history, unsafe
links, shared-source attribution, absent country semantics, unchanged
generation reuse, stale/offline/expiry behavior and an exact upstream request
ceiling. This research did not test a ReliefWeb report query or verify every
referenced publisher's terms. See [EONET implementation](EONET_SNAPSHOTS.md) for
the one fixed live acquisition result and the separately recorded release gate.
