# Next phases: from retained evidence to a living world explanation

This sequence preserves the past, current and future scope of the project. It is
not a claim that broad synthesis, two-year all-source history or continuous cloud
execution has already passed operating acceptance. Each gate can change the phases below it.

## Current blocking design gate: recurring blank globe presentation

User steering at the nine-hour checkpoint changes the presentation contract:
waiting is acceptable when actual loading is represented; up to a minute of
display delay is acceptable for smoothness. Semantic icons and visible reasoning
must replace undifferentiated dots and make the world easier to understand.

Plan the next bounded package around a hybrid presentation. Count real ready/
loading/unavailable selected layers, stage concurrent restoration and chunk entity
assembly, and measure the same16-layer workspace as the supplied report. That
report records32.17s main-thread work/8.29s blocking; Cesium execution dominates.
Its LCP is attribution, not a ready globe. Cache alone cannot remove that work.

Prepare complete dated scene editions offscreen, then commit map/icons/labels/
picking together. A10-second jitter buffer may smooth arriving data; optional
presentation delay up to60s must remain separate from provider cadence and source
age. Camera input should remain immediate. Preserve actual scene/event/publication/
capture/display times rather than silently replacing them with wall-clock now.
Preview cache keys include camera/projection, dimensions/DPR, scene UTC/lens,
source editions, selected layers/params and visual style. A Live saved image must
not masquerade as a requested historical scene.

Use category icons in a shared texture atlas/few batched collections; cluster at
global scale and reveal semantic detail as the user zooms. Evidence-linked arcs
and local relationship graphs should explain cited relationships. Hypotheses and
source reports require distinct model semantics; geographic proximity or annual
trade shares do not establish causality or physical routes.

A bounded completed-frame copy into a normal2D canvas is a creative diagnostic
fallback for the embedded presentation defect. Test readback/copy cost and keep
camera/labels/picking on the displayed frame. It does not remove Cesium execution.
Shared geographic delivery/cache is reusable across users. Remote rendered
wallboards/replay could be an optional mode; per-visitor GPU/video rendering is
an additional unverified service and a10-second video queue delays camera control.
Measure those tradeoffs before adopting another host or claiming a free solution.

At 06:14 UTC the user's image showed an opaque black graphics surface while
the Live clock, controls and separate earthquake labels remained visible. A
browser capture without reload showed the globe; DOM checks found visible
canvas dimensions, no native Cesium error panel, no app error and no saved-preview
overlay. No graphics exception explains this occurrence. This is an unresolved
intermittent presentation defect, not evidence of missing source data.

Before adding more features, isolate default drawing-buffer discard and demand
rendering from render-loop/visibility reactivation with a bounded comparison in
the affected embedded browser. The current implementation has alpha:false,
default preserveDrawingBuffer and demand rendering. These are a hypothesis, not
a proven root cause. Keep frame timing, actual presentation and render-loop
failure separate; a successful screenshot is insufficient acceptance. Do not
blindly enable continuous rendering or claim a buffer change fixes it. Agree the
comparison before modifying production, then require the user's idle/tab-return
journey to remain visible and verify its cost.

## 1. Establish continuous operating ownership

The user connected an account whose dashboard shows Workers Free. The narrow
minute collector is deployed with exact code/configuration readback, a dedicated
collect-only HMAC and one cron. Actual unattended scheduled executions and CPU
acceptance are still being checked. Keep D1/R2 evidence and the existing signed collect-only operation;
do not duplicate storage in an MCP server or move acquisition to visitor browsers.
The temporary awake-laptop bridge ends at 2026-10-12T06:39:10Z.

Gate: due acquisitions succeed without visitors or the laptop, complete receipts
read back from storage, a failed wake recovers without duplicate publication, and
actual source/capture/publication/display dates and operating costs are measured.
A nominal one-minute trigger is not a promise of one-minute provider delivery.

Budget delivery independently of source acquisition. The small deployed stream
sample is successful, but does not establish audience-scale capacity. Review the
explicit assumptions in STREAM_CAPACITY.md before increasing concurrent viewers.

Measure bounded logical references separately from unique physical objects and
growth. The local optional operator retention audit has no authenticated hosted
acceptance. Do not use it to claim whole-bucket accounting, retention expiry or
unlimited free storage. Review immutable asset delivery before approaching the
combined Worker's code/memory limits; preserve actual portfolio bytes and routes.

## 2. Finish temporal workspace and navigation ownership

Version 46 now uses one shared v4 scene codec, preserving legacy Live links and
exact History UTC/lens/rate. Saved History restores paused. An explicit link
outranks local saved state; unavailable coverage preserves the requested date
and shows its gap. Native hosted History reload, lens change, zoom/World navigation,
Live reload and explicit invalid-startup recovery passed. Camera changes retained
the exact millisecond value. This does not resolve the presentation gate above.

All camera, layer, share and startup writers must use the same codec; adding time
to Share alone lets other writers strip it. Restore time/lens before live layer
activation, cancel superseded restores and suppress intermediate persistence.

Gate: legacy and new round trips, exact UTC/lens/rate preservation, no autoplay
on History reload, elapsed-time Live restoration, explicit-link priority, malformed
or future History handling, and cancellation without a provider request. Sharing
a time is not sharing an immutable evidence edition. Keep the restoration owner
and every writer on this shared contract; do not add another independent codec.

## 3. Define entities, claims and dated relationships

Reuse stable source-item identities in src/core/world-model.js and typed receipt,
revision and membership ownership in worker/plugins/store.js. Add source-mapped
aliases for organizations, places, assets and resources. A possible match is a
candidate until supported; location or repeated wording is insufficient to merge.

Every relation revision needs its evidence locator, source edition, valid period,
first actual hosted knowledge and superseding revision. Source assertions must
remain distinguishable from the platform's inference. Group copied publications
by lineage rather than counting each outlet as independent corroboration.

Gate: corrections keep stable identity; merges and splits are reversible; a
relation resolves to retained evidence; a historical knowledge view admits no
later relation or claim. Unknown location, independence or valid time stays unknown.

## 4. Deliver one living explanatory dossier

Extend the existing cited Commission statement and Belgian annual gas scenario
mechanics into a carefully chosen explanation, using relevant retained evidence.
Do not invent a connection between these unrelated pilot topics. Reuse fenced
document/investigation publication ownership, rather than another browser AI loop.

An analysis revision binds ordered input evidence and raw revisions, reviewed
policy/model version, evidence cutoff, assumptions, alternatives and actual database
publication time. Source corrections invalidate affected work. Repeated unchanged
inputs do not generate another analysis. Local laptop inference can enrich work,
but pending inference must not block source retention or imply an always-on runtime.

Gate: every substantive explanation has inspectable original evidence; copied
sources cannot inflate confidence; changing evidence visibly supersedes an analysis;
knowledge replay excludes later analysis as well as later source revisions. Start
with one useful explanation that passes these gates before general autonomous research.

## 5. Make future scenarios reproducible, then evaluate forecasts

First durably version the existing gas-scenario.js deterministic hypothetical
arithmetic: baseline receipt, assumptions, calculation policy and outputs. Its
2024 reported data cannot become a current capacity estimate or geopolitical forecast.

Before a probabilistic forecast is served, prospectively freeze a target, issuance
time, evidence cutoff, horizon, observable outcome source, comparison baseline and
evaluation rule. Store revisions and outcomes without rewriting the original forecast.

Gate: the same baseline and assumptions reproduce the result; gaps remain missing;
retrospective calculations cannot masquerade as predictions issued in the past;
unobserved outcomes remain unevaluated. Show current explanation and a distinct
scenario action in one dossier, without adding a second competing dashboard.

## 6. Prioritize global research and delivery without losing coverage

Keep bounded baseline collection for admitted sources and their stated coverage.
Reserve bounded capacity for significant changes,
visible geographic cells, followed stories and explicit opt-in demand. Separate
acquisition, investigation, prepared tile/time delivery and rendering queues.
Camera movement can prioritize delivery and research; it cannot decide credibility.
Repeated searches can justify reviewed indexing coverage, not automatic arbitrary
URL crawling or manufactured confidence. Synthetic QA remains separate from demand.

Gate: unviewed regions keep the admitted sources' baseline coverage; panning creates bounded coalesced
work; expensive jobs cannot starve collection; historical playback issues no
per-frame acquisition; privacy-preserving demand collection has an actual user policy.

## 7. Extend reviewed plugins and the calm interface

Extend worker/plugins/registry.js with explicit source/analysis capabilities, rights,
coverage, clocks, lineage, resource limits and replay semantics. Extend MCP tools in
worker/site-mcp.js to expose the same bounded stored relationship and scenario
operations once those operations exist. Current MCP metadata does not establish
that capability. Authentication and an actual connected owner must be proven before
enabling writer access. MCP metadata alone is not an installed integration or scheduler.

Keep a single visual hierarchy: spatial evidence on the globe; one explanation
dossier; a compact clock and expandable timeline. Use coherent icons and accessible
labels, restrained accent colors, quiet transitions and progressively disclosed
source/assumption details. Source checking updates must preserve selection, focus
and disclosures. Continuous animation may interpolate supported trajectories or
calculated astronomy; it must not fabricate incidents or silently convert estimates
into observations. Missing source frames keep their gaps and last-known dates.

Gate: newcomer and historical-research journeys work by keyboard and pointer;
mobile panels do not compete; camera/zoom remains responsive; unsupported history
is understandable; high-resolution label legibility is actually inspected; measured
render and delivery budgets remain stable during updates and cancellation.

## Re-examination loop

For each coherent package: name the user outcome and dependencies, review existing
capabilities and primary source evidence, implement the smallest usable slice,
verify meaningful ownership/data gates, then exercise actual deployed journeys.
Record what is local, published, observed, inferred and still unavailable.

If a gate fails, fix the fundamental contract before broadening the feature. If a
better method or new source capability appears, compare its operating evidence,
rights, integration cost and bounds, and revise downstream phases. Preserve prior
complete evidence and a rollback point. Finish the approved release before starting
an unrelated slice; the nine-hour review boundary is not platform completion.
