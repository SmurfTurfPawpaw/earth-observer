## Re-examination loop

For each coherent package: name the user outcome and dependencies, review existing
capabilities and primary source evidence, implement the smallest usable slice,
verify meaningful ownership/data gates, then exercise actual deployed journeys.
Record what is local, published, observed, inferred and still unavailable.

If a gate fails, fix the fundamental contract before broadening the feature. If a
better method or new source capability appears, compare its operating evidence,
rights, integration cost and bounds, and revise downstream phases. Preserve prior
complete evidence and a rollback point. Finish the approved release before starting
an unrelated slice; the nine-hour review boundary is not platform completion.
