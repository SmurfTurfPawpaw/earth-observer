# Shared retained scenes

The three monitoring layers have separate owners: worldwide acquisition and
retained history; a durable coverage/priority scheduler; and selected-cell browser
delivery. Viewing a region does not acquire a source or restrict global acquisition.

## Closed source registry

USGS rolling-day M2.5+ seismic reports (up to500) and the completed seven-day
GDACS notice sample (up to100) use one builder, four fixed current/prior R2 slots,
one read-only regional API, one browser codec/cache implementation and one native
billboard renderer. Source wrappers supply factual title, symbol, color, picking
properties and their source-native provenance. They do not implement new queues,
camera listeners, render loops, provider fetches or alternate completeness rules.

The old USGS two slots remain its verified transitional input. New derivatives
add at most1.5MiB. Preparation runs once per source on an admitted authenticated
coverage wake and reuses the wake's retained input. Unchanged source heads cause
no derivative rewrite. Public GETs do not prepare, acquire or repair storage.

Every delivered scene conserves mapped reports: selectedMapped equals individual
features plus residual cluster counts. Unmapped notice metadata stays available;
no reported location is invented. Summary positions are cell centers and never
pretend to be reported locations. A single vector-texture badge carries category
and exact count, without overlapping native labels or browser-font dependence.

## Display priority is not established consequence

Source attention is evaluated per UTC minute: recent actual USGS earthquakes M6+
or source GDACS Red assessments can become at most16 individual highlights.
Other reports, including overflow, remain in counted category clusters. Expiring
attention alters a view edition, not a factual revision, source capture or
historical evidence. Reach stays unresolved: source severity alone does not prove
country, continental or global consequences. Repeated syndication is not
independent corroboration.

## Functional viewport interest

One production browser owner may renew a coarse center sector while an applicable
layer is active. It sends at most one request per minute, no exact coordinates,
search text, cookies, identity or analytic count. Interest expires after two
minutes. World/continent/sky views, hidden tabs, History and marked diagnostic
sessions submit none. Opt-in search-demand analytics remain disabled.

The same-origin endpoint accepts only a fixed viewport schema with up to4 valid
sector IDs; normal browser input uses1. Per-process request limits,512-byte body,
deadline, fixed priority30, expiry and the durable120-task ceiling bound work.
Admission is an interest acknowledgement, not a guaranteed queue slot or fetch.
Higher-priority work can displace one lower-priority queued task when the global
queue is full; repeated or equal-priority requests cannot evict existing work.
Only authenticated wakes process it, and regular worldwide capacity remains
reserved. This endpoint does not yet implement durable followed-subject ownership.

## Remaining gates

The camera footprint currently coarsens uniformly. True center emphasis needs a
finer focus partition that subtracts its exact feature IDs from coarse residual
groups at one source edition, so expanded detail never duplicates counts.
Evidence-backed consequence reach and durable followed-subject capabilities are
separate next-phase work. This package does not extend History to years or restore
close-up aerial/terrain detail. Native screenshot evidence also cannot settle the
user's earlier embedded-browser compositor black-screen report.

A real500-report fixture encodes289,062B of stored source data,2,568B of complete
coarse view, and284,127B of individual-feature view. The latter exceeds the250KiB
view/270KiB delivery limits and returns a non-preparing `scene-byte-budget`
response while retaining the prior complete view. Every delivered count is
conserved; this is an explicit remaining dense-detail limitation, not truncation.

Missed coverage wakes accrue capped durable debt and borrow at most two optional
slots; a due priority gets reserved optional capacity. Completion timestamps are
actual storage clocks. Exact30-second runtime execution remains unverified; a
long outage cannot guarantee a one-hour wall-clock sweep.
