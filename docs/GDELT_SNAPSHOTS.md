# Scheduled global topic discovery

The default source is **GDELT Global Knowledge Graph 2.1**, sampled by a scheduled job rather than live DOC API requests from visitors. It retains only original WEB source links and reviewed topic/country mentions. The public output is the single bounded `intelligence-data` release asset `gdelt.snapshot.json`. There are no article bodies, copied headlines, quotations, photos, sentiment scores or asserted incident coordinates. Cards say **Topic mention**, never verified incident.

## Source rights and interpretation

[GDELT terms](https://www.gdeltproject.org/about.html) permit commercial use and redistribution with a GDELT citation and link. Earth Observer retains this credit and each original publisher URL. Permission to reuse this dataset does not supply permission to copy publishers' articles or photographs.

The [GKG 2.1 codebook](https://data.gdeltproject.org/documentation/GDELT-Global_Knowledge_Graph_Codebook-V2.1.pdf) describes 27 tab-delimited fields despite the CSV extension. Only source collection `1` (WEB) is admitted. The small allowlist in `server/hosted/gdelt-gkg.js` uses exact identifiers reviewed against the [official theme lookup](https://data.gdeltproject.org/api/v2/guides/LOOKUP-GKGTHEMES.TXT), covering diplomacy/conflict/elections, trade/economy/finance/logistics and disasters/emergency response. A detected topic is a machine classification, not a summary of the publisher's claims.

Geography uses **FIPS**, not ISO. The explicit current-country crosswalk cites [GDELT's FIPS lookup](https://www.gdeltproject.org/data/lookups/FIPS.country.txt). Its outdated Guinea/Slovakia labels are corrected against [NIST's FIPS codebook](https://nvlpubs.nist.gov/nistpubs/Legacy/FIPS/fipspub10-4.pdf) and [USGS country codes](https://www.pwrc.usgs.gov/BBL/Bander_Portal/login/country_codes.php): `GV` is Guinea (`GN`), `EK` is Equatorial Guinea (`GQ`) and `LO` is Slovakia (`SK`). Ambiguous, obsolete and ocean entries without a clear current ISO counterpart are omitted. Country filtering means **country mentioned**, never publisher nationality or incident location. No GKG coordinate is exposed. For example, FIPS `GM` becomes ISO `DE`, while FIPS `AU` becomes ISO `AT`.

## Version 2 contract

`schemaVersion: 2`, `kind: "gkg-topic-sample"` has `generatedAt`, fixed GDELT `source`, `coverage` and three categories: `geopolitics`, `economy`, `disasters`. Each retains at most 80 records. Each record has `kind: "topic-mention"`, original canonical URL/domain, reviewed theme identifiers, ISO `mentionedCountries`, batch ID, batch time as `indexedAt` and actual completed retrieval time as `retrievedAt`. Its title is a neutral theme label, never a reconstructed headline. Original `publishedAt`, `observedAt`, `publisherCountry` and language remain null. Original timestamps remain unchanged when records survive later refreshes.

The rolling sample merges only a validated previous copy of the project's own release with the new batch. It deduplicates URLs and balances countries/publisher domains before applying topic limits. Previously omitted records cannot be recovered, so this is a sample rather than an archive or exhaustive search. Individual records older than 24 hours of batch time are removed during generation and serving.

Coverage retains exact `processedBatches` (ID, retrieval time, parsed row count and matching-record count), `windowStart`, `windowEnd` and `sampleGaps`: missing 15-minute intervals between observed endpoints. Nothing claims to process intervals before the first observed batch. Up to 96 unique batches fit the 24-hour window; delayed or skipped scheduled runs observe fewer. Metadata must fit within 1 MiB. The portable validator rejects unknown fields, article content, coordinates, changed labels/provenance, invalid times, coverage mismatches and excess counts.

## Acquisition and publication

The Node generator reads the small official `gdeltv2/lastupdate.txt` manifest and accepts only the fixed HTTPS host and timestamped `YYYYMMDDHHMMSS.gkg.csv.zip` pattern. Declared compressed length and MD5 must match. It validates the single expected CSV entry and CRC and processes it without extracting files. ZIP parsing and Node decompression belong only to the scheduled job, never the Worker/browser graph. Limits are 16 MiB compressed, 128 MiB expanded, 50,000 rows, 512 KiB per TSV row and 10,000 retained candidates. Integrity, timeout, format or limit failure skips publication and preserves the previous release. Default generation makes no DOC API requests.

The small manifest inspected on 11 October 2026 declared the `20261011013000` batch as 42,855 compressed bytes for Events, 59,830 for Mentions and 2,061,078 for GKG. These are one quiet sample's sizes, not guaranteed maxima. Events are smaller but encode CAMEO actor interactions, which do not replace broad general/economic/disaster topics. Research fetched only the manifest/documentation, with no archive download.

The GitHub workflow requests runs at minutes 2, 17, 32 and 47 and supports dispatch. This targets each source's 15-minute batch cadence, rather than waiting another 30 minutes between acquisitions. It cannot produce new GKG content before GDELT publishes it. Exact batches/timestamps disclose scheduling delays and skipped intervals. Publication is serialized; only a completely validated result is written by temporary-file rename and uploaded. Failed generation never replaces the asset. GitHub `--clobber` is not transactional: interrupted replacement can temporarily remove the file, so the reader retains last-good validated state.

[GitHub documents that scheduled runs may be delayed or dropped](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). The configured cadence is not a hard freshness or delivery guarantee. As inspected at `2026-10-11T12:09:31Z`, the latest actual GDELT publication was the manual `09:57:39Z` upload, and no subsequent workflow run existed; the cron was active on the default branch with Actions enabled. That gap was an absent observed dispatch, not a new provider failure. Autonomous execution at the revised cadence remains to be verified from actual run and asset history. A green workflow that skips generation does not establish publication.

## Shared serving and optional live discovery

Node and Worker share a lazy reader that revalidates the small project's own release asset at most once every **60 seconds per reader instance**, with coalescing across visitor filters and provider backoff after failure. A valid response entity tag enables `If-None-Match`; an unchanged response advances only `snapshotCheckedAt`, retaining the actual download's `snapshotRetrievedAt` and every source generation, retrieval and indexing timestamp. Revalidation uses `Cache-Control: no-cache`. It performs no GKG ZIP download or processing in the Worker. This reduces the delivery delay after a successful publication, rather than calling the original source every minute.

Optional private R2 persistence preserves last-good data, valid entity tags and the check clock across instances. Its conditional-write atomic lease permits one release check per 60-second lease; other instances read the last completed shared snapshot, retaining their current generation if shared storage is older. If the owner is still acquiring, readers can retry the bounded shared-state read after one second without acquiring the network lease again. Optional reads, writes and claims have a default one-second deadline, so unavailable or stalled storage falls back to local coalescing rather than preventing successful network replies. Without functioning atomic storage, the network bound is per reader instance, not globally across every Worker instance. The **30-minute stale threshold** and legacy schema-1 **30-minute retrieval validation window** are separate from the faster release-check interval. Older data is labeled, timestamps are retained, and snapshots or individual batch records beyond 24 hours are withheld, including when the release server returns `304`. Country/topic filters run locally and cannot download bulk data or publisher pages. Topic input matches reviewed labels and publisher domains, not article bodies.

Version 1 DOC headline/link snapshots remain readable. `GDELT_LIVE_FALLBACK=1` is an operator opt-in only when scheduled data is unavailable. Existing bounded queries, spacing, HTTP 429 and Retry-After backoff remain. The option is absent from the public baseline. Similar generated topic labels never group as corroboration. Hazard records retain separate provenance and indicative grouping.

Synthetic tests validate contracts and failure paths; they do not establish live coverage. One actual bounded generation succeeded on 11 October 2026 at `08:47:34.825Z`, processing the official `20261011084500` batch: 2,150,907 compressed bytes, 462 parsed rows and 306 topic matches. MD5 and ZIP CRC both validated. The resulting 203,970-byte JSON retained 80 geopolitics, 69 economy and 53 disaster records. This demonstrates working metadata discovery for that one batch, not complete global coverage or confirmation of publisher claims. No DOC API or original article request was made. Publishing the release and consuming it from the deployed site remain separate checks.
