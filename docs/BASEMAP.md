# Roads and place names

The default map draws OpenFreeMap's OpenMapTiles vector data into small Canvas tiles used by the existing Cesium globe. This original compact style shows mapped roads, settlements, water, parks and building footprints. It uses installed browser fonts and the existing PBF decoder dependencies. It adds no second WebGL renderer, map SDK, font/glyph service or sprite downloads.

The [OpenFreeMap homepage](https://openfreemap.org/) explicitly permits commercial use of its public instance and requires OpenMapTiles and OpenStreetMap attribution. Its [current terms](https://openfreemap.org/tos/) describe an as-is service, responsible integration and no unauthorized automated collection. This integration requests visible map tiles on demand; it does not bulk-download regions or prefetch OSM public raster tiles. Linked OpenFreeMap, © OpenMapTiles and © OpenStreetMap contributor credits remain onscreen. The [OpenMapTiles schema](https://openmaptiles.org/docs/schema/) documents the mapped feature and place-name fields. Checked 2026-10-11.

The validated versioned TileJSON source currently supplies native zooms 0–14. Views through zoom 18 redraw the same parent geometry into the requested child tile. This improves line/text sharpness when zooming; it does not add finer source observations, updated imagery or live traffic. Mapping completeness, names and boundaries reflect source data rather than an Earth Observer verification claim. Building footprints are flat mapped outlines, not newly generated 3D measurements.

Labels use smaller 8–10 pixel fonts with zoom-specific quotas rather than a fixed allowance of 100 names per tile. Country names require an explicit prominence rank and appear only at zooms 1–4; city names begin at zoom 5, towns at 8, and road names at 14. More local settlement names appear at closer zooms. Country and city names therefore do not compete at the same zoom. Repeated names are suppressed within each tile. Measured glyph bounds, halos and rotated road-name bounds must fit completely inside a three-pixel tile margin, and road names must fit their selected segment. A name near a tile seam can be omitted rather than producing a clipped fragment; this compact renderer does not implement a separate global label-placement engine.

`viewer.earthBasemap` exposes `setMode('map' | 'imagery')`, `getState()` and a `ready` promise. Mode reflects the user's selection synchronously; state also identifies whether the actual displayed base is map, coarse NASA imagery or bundled imagery. Selecting NASA imagery cancels owned map requests. NASA is hidden while the opaque street map loads and displays, avoiding refinement requests for a covered imagery layer.

The adapter permits four active Cesium-scheduled tile requests, shares native parent fetches across closer child views and declines excess work for a later frame. Reads have 12-second limits, reject redirects and accept at most 4 MiB per PBF. Decoding stops beyond 30,000 selected features or 200,000 coordinate points. Native geometry has a 16 MiB estimated-storage LRU budget; rendered 256×256 Canvas tiles have a 64-entry / 16 MiB pixel-storage cache. Cesium's separate displayed imagery textures follow the globe's existing cache limit. Closing or destroying the viewer cancels owned transports and clears adapter caches.

A 512-pixel raster was evaluated for this label repair and not enabled. In the installed Cesium 1.138 source, imagery level selection depends on `tileWidth`: doubling it chooses one coarser source level for the same terrain spacing. Doubling geometry and font scale together would therefore not reliably reduce the displayed text size, and the same 16 MiB raster budget would hold only 16 canvases. The targeted density and full-label placement repair keeps the existing resolution, source-level behavior and cache capacity. A future raster-resolution change needs a browser profile and coordinated styling/level selection rather than a canvas-size change alone.

Bundled public-domain Natural Earth imagery paints first. Missing source metadata prevents map initialization and selects coarse imagery, with a 30-second retry cooldown. Individual tile failures keep the street layer enabled above the bundled base: Cesium can accept a saved child even when its ancestors failed. The layer reports partial coverage rather than discarding reachable detail after a run of misses. The map button retains that explanation in its tooltip and accessibility description. Unknown areas remain gaps; they do not acquire invented roads.

Saved metadata alone does not establish saved street coverage. The provider counts a saved tile only after a valid PBF carrying the browser cache's `x-earth-map-cached-at` marker has been decoded. That marker records browser-storage time, not the source map's observation time. Coverage notices distinguish saved detail from general partial coverage. Switching to imagery still cancels owned street requests; initialization failures retain the existing coarse fallback.

The globe renders one drawing-buffer pixel per CSS pixel across device pixel ratios. Previously, Cesium's browser-recommended resolution already ignored device pixel ratio, while an additional `1.5 / devicePixelRatio` scale reduced detail on dense screens. Settled street views now use a 1.5-pixel screen-space error; movement and imagery use 3 to avoid extra refinement during navigation. After movement ends, the globe requests refinement at the same bounded native zoom and cache limits. This changes selection and display quality, not source resolution.

Ten focused tests cover source admission/linked attribution, native-parent overzoom selection, genuine PBF geometry and synthetic labels, polygon holes, country/city zoom and rank selection, complete text and rotated bounds, oversized glyph ink, repeated names, per-zoom density limits, native fetch sharing, LRU bounds, Cesium backpressure, cancellation/reopening and oversized-body rejection. The synthetic names test rendering behavior and are not geographic facts. These checks establish layout rules and lifecycle behavior; the next release still requires visual browser verification of the changed labels.

Nine additional coverage/rendering-policy tests cover event cleanup, movement refinement, honest saved markers and partial failures. One drives Cesium's actual imagery state machine through eight failed ancestors followed by a genuine saved native zoom-14 vector tile, then checks child acceptance and shared overzoom. Its GPU completion is mocked; it does not establish WebGL visual recovery. The same next release still needs an actual browser reload and offline check.

Saved and shared camera views are validated before restoration against the actual viewport and the existing altitude ceiling. A separate CPU-only Cesium camera checks the Earth's enclosing sphere against the frustum. Only a view whose whole Earth is outside that frustum is recovered to a downward pitch with zero roll; position, heading and the bounded altitude remain intact. Local tilts and partially visible global views are preserved. The tilt button also chooses an angle whose center ray intersects the WGS84 ellipsoid, with a four-degree margin inside the horizon, when the requested 45-degree global tilt would miss Earth. It remains a reversible toggle. Direct camera movement and dragging stay freely explorable.

The published v22 desktop geometry reproduced a fully invisible Earth at 18,000 km altitude with horizontal or 45-degree tilted views. This establishes a camera-flow defect, not the cause of the user's reported black screen. Twenty-four focused tests across `globe-framing.test.mjs`, `navigation.test.mjs`, `workspace.test.mjs` and `scene-preview.test.mjs` pass in the working tree. They use the installed Cesium camera/frustum and ray/ellipsoid calculations to verify saved/shared recovery, the altitude clamp, preserved local and partial portrait tilts, a working global tilt button and pressed state, unchanged live camera exploration, destroyed-viewer handling and existing preview handoff. This camera repair is pending publication and has no new visual browser proof yet.

The renderer's unused default ion logo is cleared through the documented [CreditDisplay.cesiumCredit API](https://cesium.com/learn/cesiumjs/ref-doc/CreditDisplay.html), without hiding data-provider credits. This build uses no ion services. The SDK's Apache license and distributed third-party notices remain in the repository and public notices.
