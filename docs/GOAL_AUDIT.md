## Search-contract findings included in v22

This review inspected the portable index, scheduled reader, hosted API and browser derivation/validation. It also used small synthetic in-process fixtures; no new upstream archive, live query, public demand event or evidence submission was made. A separate agent independently reviewed the browser/API grouping and expiry paths.

| Finding | Reproduction and implication | Status in the recorded release |
| --- | --- | --- |
| Default cards bypassed expiry during a long network outage | Retrieve one valid indexed GKG record, advance by 24 hours and fail the next fetch. The default card remained `ready`; a local search expired it, but clearing the query initially restored it. A subsequent review also found failed-refresh derivation was missing. | **Fix committed and included in v22**: default/related cards use active index identities; refresh failure recomputes expiry and marks retained source state stale. Synthetic reproduction returned zero expired cards/index records with the outage error. Outage/clear-query regressions passed; no 24-hour production outage was induced. |
| Local search and legacy API grouping differed | Two nearby/time-matched USGS/GDACS earthquake metadata records previously produced two singleton browser cards versus one legacy API card with one related link. | **Fix committed and included in v22**: both use `src/core/intelligence-grouping.js`, preserving query relevance and original primary/related metadata. Topic mentions stay separate because a shared machine label does not establish one story; related links do not imply independent confirmation. Production local search worked, while detailed grouping parity is established by regressions. |
| Selected topic disagreed with compact label | A URL carrying armed-conflict, sanctions and trade themes, primarily indexed under geopolitics, matched `category=economy&q=Trade` but retained a geopolitics compact title. | **Fix committed and included in v22**: category projection rebuilds the compact title from that category's reviewed themes. Full reviewed topics remain searchable beyond the first three entries. The edge case has a contract regression, not a separately recorded production interaction. |
| Curly-apostrophe and reviewed-ID validation needed parity | The local form accepted `Côte d’Ivoire`, while legacy API `q` rejected `’`; raw reviewed identifiers also needed translation before punctuation validation. | **Fix committed and included in v22**: shared `discoveryQueryText` translates exact reviewed IDs such as `WB_698_TRADE`; both entry validators permit curly apostrophes/domains and retain the 64-character limit. Unknown IDs are not promoted to reviewed subjects. These edges have contract regressions; ordinary production free-text search was observed to remain local. |

The source-generation contract was checked explicitly: the backend publishes complete unfiltered retained source candidates, so repeated country/topic filters do not masquerade as a new complete generation. Source replacement removes superseded generation records; same-batch URL/kind deduplication merges metadata, while a newer batch cannot give older country mentions a newer expiry. Previously acquired sources absent from a later response retain only their original generation/expiry and coverage; they are not represented as newly acquired data.

API candidate/byte caps, shared acquisition, source and individual-batch expiry, all-term matching, reviewed taxonomy and relevance after legacy grouping have focused tests. Earlier runs passed 37 index/backend/reader/GKG tests, 20 generator/browser tests and a later 25-test expiry audit. Shared-grouping/parity regressions are committed in the v22 runtime. The release record separately reports 1,011 full-suite passes at `5f69738`, followed by the final revision's GitHub Check and build/routing checks. None of those counts certifies subsequent uncommitted map/CCTV changes or every production edge case.
