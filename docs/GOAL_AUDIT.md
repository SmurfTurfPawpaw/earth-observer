## Read-only search-contract findings

This review inspected the portable index, scheduled reader, hosted API and browser derivation/validation. It also used small synthetic in-process fixtures; no new upstream archive, live query, public demand event or evidence submission was made. A separate agent independently reviewed the browser/API grouping and expiry paths.

| Finding | Reproduction and implication | Status at audit time |
| --- | --- | --- |
| Default cards bypassed expiry during a long network outage | Retrieve one valid indexed GKG record, advance by 24 hours and fail the next fetch. The default card remained `ready`; a local search expired it, but clearing the query initially restored it. A subsequent review also found failed-refresh derivation was missing. | **Fixed in the working tree**: default/related cards are filtered through active index identities, refresh failure recomputes expiry and marks retained source state stale. Reproduction returned zero expired cards/index records with the original outage error. Both outage/clear-query regressions passed in the later 25-test targeted run; final deployed inclusion remains to be verified. |
| Local search and legacy API grouping differed | Two nearby/time-matched USGS/GDACS earthquake metadata records previously produced two singleton browser cards versus one legacy API card with one related link. | **Fixed in the working tree**: both use `src/core/intelligence-grouping.js`, with query grouping preserving index relevance and original primary/related metadata. The server compatibility exports reference the same function. Topic mentions remain separate because a shared machine label is not evidence of one story; related links never imply independent confirmation. |
| Selected topic disagreed with compact label | A URL carrying armed-conflict, sanctions and trade themes, primarily indexed under geopolitics, matched `category=economy&q=Trade` but retained a geopolitics compact title. | **Fixed in the working tree**: category projection rebuilds the compact title from that category's reviewed themes. Full reviewed topics remain searchable, including those beyond its first three entries. |
| Curly-apostrophe and reviewed-ID validation needed parity | The local form accepted `Côte d’Ivoire`, while legacy API `q` rejected `’`; raw reviewed identifiers also needed translation before punctuation validation. | **Fixed in the working tree**: browser/API entry points use `discoveryQueryText` to translate an exact known identifier such as `WB_698_TRADE` to `Trade`; both validators permit curly apostrophes and publisher domains and retain the 64-character query limit. Unknown identifiers are not silently promoted to reviewed subjects. Free text remains local in the ordinary browser flow. |

The source-generation contract was checked explicitly: the backend publishes complete unfiltered retained source candidates, so repeated country/topic filters do not masquerade as a new complete generation. Source replacement removes superseded generation records; same-batch URL/kind deduplication merges metadata, while a newer batch cannot give older country mentions a newer expiry. Previously acquired sources absent from a later response retain only their original generation/expiry and coverage; they are not represented as newly acquired data.

API candidate caps, serialized-byte caps, shared acquisition across queries, source and individual-batch expiry, all-term metadata matching, reviewed taxonomy and relevance after legacy grouping have focused tests. The earlier implementation run passed 37 index/backend/reader/GKG tests and 20 generator/browser tests; the later expiry audit run passed 25 browser/index/API tests including the two new regressions. Shared-grouping and parity regression sources are also present in the current worktree. These are named targeted runs, not the final repository-wide count or proof that every later concurrent edit passed.
